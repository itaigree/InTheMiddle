# מקום באמצע

מכניסים שתי נקודות יציאה, ומקבלים מקומות בילוי שנמצאים בערך באותו זמן נסיעה משני הצדדים:
בתי קפה, קניונים, פארקים, מקומות טבע ונוף, מסעדות ואטרקציות.

**כתובת האפליקציה:** https://itaigree.github.io/InTheMiddle/

## מה האפליקציה עושה

1. ממירה את שני השמות שהוקלדו לנקודות על המפה (עם השלמה אוטומטית בזמן ההקלדה).
2. מחשבת את המסלול בין שתי הנקודות, ובודקת זמני נסיעה משני הצדדים לנקודות לאורכו.
   כך היא מוצאת את הנקודה שבה **זמן** הנסיעה שווה, ולא רק את אמצע המרחק.
3. מחפשת סביב הנקודה הזו מקומות מהסוגים שנבחרו. כשיש שם מעט מקומות (או שאי אפשר להגיע לאף אחד מהם),
   היא מרחיבה את החיפוש בהדרגה: כל פעם פי שניים, עד רבע מאורך הדרך (בין 5 ל-30 ק״מ מנקודת האמצע).
4. בודקת לכל מקום כמה זמן לוקח להגיע אליו מכל צד, ומדרגת לפי ממוצע הנסיעה של שני הצדדים,
   לפי ההפרש ביניהם ולפי הדירוג של המקום.
5. מציגה מפה ורשימה, עם ניווט ב-Waze, קישור למקום עצמו ב-Google Maps ושיתוף בקישור. לחיצה על מקום ברשימה מקרבת
   את המפה אליו, ומפה קטנה בפינה ממשיכה להראות את כל החיפוש (לחיצה עליה מרחיקה בחזרה).

כל צד בוחר אם הוא מגיע ברכב או בתחבורה ציבורית. אפשר גם לבחור זמן יציאה עתידי,
וזה חשוב במיוחד בתחבורה ציבורית (למשל בשבת).

**מה חשוב יותר?** כמעט אף מקום לא נמצא בדיוק באמצע, אז אפשר לבחור על מה מוותרים:
- **זמן שווה:** שני הצדדים נוסעים כמעט אותו זמן, גם אם שניהם נוסעים יותר.
- **מאוזן** (ברירת המחדל): גם זמן דומה וגם דרך קצרה.
- **פער גמיש:** מותר פער גדול יותר בזמני הנסיעה בין שני הצדדים, בשביל מקום קרוב יותר.

הבחירה משנה רק את הסדר של המקומות, ולכן שינוי שלה אחרי החיפוש מסדר את הרשימה מחדש מיד, בלי חיפוש נוסף.

**סינון "רק בתוך הקו הירוק":** משמיט מקומות ביהודה ושומרון וברצועת עזה. ירושלים (כולל השכונות
שמעבר לקו) ורמת הגולן נשארות. כשהסינון פועל גם הדרך עצמה לא עוברת ביהודה ושומרון: אם הדרך המהירה עוברת
שם (למשל ירושלים–ירוחם דרך חברון), האפליקציה בוחרת דרך חלופית שלא עוברת שם, או מכריחה את הדרך לעבור
בצמתים שבתוך הקו (כביש 1 בשער הגיא, כביש 6, כביש 31 ועוד, בקובץ `site/js/core/detour.js`), ומחפשת סביב
האמצע של הדרך הזו. גם זמני ההגעה למקומות נמדדים אז מהדרך הזו. קטע קצר של עד 3 ק״מ מותר, ושטח ההפקר
בלטרון (כביש 1 וכביש 3) לא נחשב. הגבולות הם אזור "יהודה ושומרון" ורצועת עזה מ-OpenStreetMap,
מפושטים לדיוק של כ-30 מטר. לבנייה מחדש של הקובץ `site/data/green-line.json`:
`node tools/build-green-line.mjs` (צריך גישה לרשת).

**סינון "סגור בשבת":** משאיר רק בתי קפה ומסעדות ששעות הפתיחה שלהם (מ-Google או מ-OpenStreetMap)
מראות שהם סגורים מיום שישי ב-19:00 עד שבת ב-17:00, זמן שנמצא בתוך השבת בכל עונות השנה.
זה סימן טוב לכשרות ולא אישור. מקומות שאין להם שעות פתיחה במפה לא מוצגים כשהסינון פעיל,
ולכן במצב OpenStreetMap הוא משאיר מעט מקומות. סוגי מקומות אחרים (פארקים, קניונים וכו׳) לא מושפעים.
כרטיס של בית קפה או מסעדה שסגורים בשבת מסומן ב"סגור בשבת" גם בלי הסינון.

**שיתוף:** שורת הכתובת נשארת הכתובת של האתר עצמו, כך ששיתוף שלה משתף את האפליקציה.
קישור לחיפוש מסוים מקבלים מכפתור השיתוף שליד התוצאות.

## מקורות הנתונים

| מצב | מתי | מה מקבלים |
| --- | --- | --- |
| **Google Maps** | כשמוגדר מפתח API ועוד לא נגמרה המכסה היומית | דירוגים, תמונות, שעות פתיחה, זמני נסיעה שמביאים בחשבון פקקים, תחבורה ציבורית |
| **OpenStreetMap** | בלי מפתח, או כשהמכסה של Google נגמרה | מפה וזמני נסיעה ברכב, מקומות מ-OpenStreetMap, בלי דירוגים |

המעבר אוטומטי: כש-Google מחזירה שגיאת מכסה (או שגיאת מפתח), האפליקציה עוברת ל-OpenStreetMap,
מציגה הודעה קצרה, וחוזרת לנסות את Google אחרי שהמכסה היומית מתאפסת.

## הקמה (פעם אחת)

### 1. GitHub Pages

1. **להפוך את ה-repo לציבורי:** ‏Settings ← General ← בתחתית העמוד, Danger Zone ← **Change visibility** ← Public.
   (ב-GitHub חינמי, Pages עובד רק עם repo ציבורי. מפתח ה-API לא נשמר ב-repo אלא ב-Secret, אבל הוא כן
   מופיע באתר עצמו בקובץ `config.js`, כמו בכל אתר שמשתמש ב-Google Maps. מה שמגן עליו הן ההגבלות והמכסות שבסעיף 2.)
2. **להפעיל את Pages:** ‏Settings ← Pages ← Build and deployment ← Source: **GitHub Actions**.
   (לא "Deploy from a branch": במצב הזה GitHub מפרסם את תיקיית השורש, והאתר מציג את קובץ ה-README הזה במקום האפליקציה.)
3. כל push ל-`main` מריץ בדיקות ומפרסם את האתר. אפשר לראות את ההרצות בלשונית **Actions**.

גם בלי מפתח של Google האתר עובד, במצב OpenStreetMap.

### 2. מפתח Google Maps (בשביל דירוגים, תמונות ותחבורה ציבורית)

1. נכנסים ל-[Google Cloud Console](https://console.cloud.google.com/) ← בוחרים פרויקט ← **New Project** (למשל `InTheMiddle`).
2. **Billing** ← מקשרים חשבון חיוב (כרטיס אשראי). בלי חשבון חיוב, Google מגבילה לבקשה אחת ביום.
   המכסות היומיות שבסעיף 5 שומרות שהשימוש של האפליקציה עצמה יישאר בחינם. כדי להגן גם מפני מי שמעתיק את המפתח,
   מומלץ להוסיף את העצירה המוחלטת שבסעיף 7.
3. **APIs & Services ← Library** ← מפעילים את שלושת אלה בדיוק:
   - **Maps JavaScript API**
   - **Places API (New)**
   - **Routes API**

   (לא צריך את הגרסאות הישנות: Places API, ‏Directions API, ‏Distance Matrix API.)
4. **Google Maps Platform ← Keys & Credentials ← Create credentials ← API key**, ואז עורכים את המפתח:
   - **Application restrictions** ← Websites ← מוסיפים `https://itaigree.github.io/*`
   - **API restrictions** ← Restrict key ← מסמנים את שלושת ה-API מסעיף 3
   - Save. השינוי נכנס לתוקף תוך כמה דקות.
5. **מכסות יומיות.** זה החלק שמבטיח שלא יהיה חיוב. מפתח של אתר תמיד גלוי בדפדפן, ומי שמעתיק אותו יכול לקרוא
   גם לשירותים יקרים יותר מאלה שהאפליקציה משתמשת בהם. לכן צריך לשים מכסה על **כל** שורה שמסתיימת ב-**per day**
   בשלושת ה-API, ולא רק על מה שהאפליקציה צורכת. ב-**Google Maps Platform ← Quotas** בוחרים כל API, מוצאים כל שורה כזו,
   לוחצים על העיפרון, מבטלים את Unlimited ומזינים ערך:

   | API | מכסה (השם המדויק עשוי להיות מעט שונה) | ערך יומי מומלץ |
   | --- | --- | --- |
   | Places API (New) | SearchNearbyRequest per day | **32** |
   | Places API (New) | SearchTextRequest per day | **32** |
   | Places API (New) | GetPlaceRequest per day | **32** |
   | Places API (New) | GetPhotoMediaRequest per day | **32** |
   | Places API (New) | AutocompletePlacesRequest per day | 300 |
   | Places API (New) | כל שורה אחרת שמסתיימת ב-per day | **0** |
   | Routes API | ComputeRoutes per day | **32** |
   | Routes API | ComputeRouteMatrix: מכסה יומית שנספרת ב**אלמנטים** (ראו הערה) | **320** |
   | Maps JavaScript API | Map loads per day (אם קיים; המפה הקטנה בפינה היא טעינה נוספת, רק כשמתקרבים למקום) | 300 |

   **מאיפה המספרים:** בכל חודש Google נותנת בחינם 1,000 חיפושי מקומות עם דירוגים ושעות פתיחה,
   1,000 תמונות ו-10,000 מרוב השאר. 1,000 חלקי 31 ימים זה בערך 32 ביום, והמספר הזה שומר על כל שירות
   מתחת לחינם גם אם מישהו קורא לו בדרך היקרה ביותר. חיפוש אחד באפליקציה שולח בקשת חיפוש מקומות אחת לכל סוג
   מקום שנבחר (4 כברירת מחדל), ולכן יוצאים **כ-8 חיפושים ביום עם Google** (חיפוש שצריך להרחיב שולח עוד סבב כזה
   לכל הרחבה, עד שניים). אחרי זה, ועד חצות לפי שעון קליפורניה
   (בסביבות 10:00 בבוקר בישראל), האפליקציה עוברת אוטומטית ל-OpenStreetMap.

   **הערה על ComputeRouteMatrix:** השירות הזה מחויב לפי אלמנטים (מוצא × יעד), ובקשה אחת יכולה להכיל עד 625.
   אם בקונסול יש לו מכסה יומית שנספרת באלמנטים, שמים 320, וזה מספיק לשימוש של האפליקציה (שמשתמשת רק ברמה
   הבסיסית). אבל מי שמעתיק את המפתח יכול לבקש את הרמות היקרות יותר (למשל עם פקקים), שהמכסה החינמית שלהן קטנה יותר,
   ואם יש רק מכסה לפי מספר בקשות או לפי דקה, היא לא חוסמת כמות גדולה של אלמנטים. לכן העצירה המוחלטת שבסעיף 7
   היא ההגנה היחידה שסוגרת את זה לגמרי.
6. **Map ID** (בשביל הסמנים במפה): ‏Google Maps Platform ← **Map management ← Create Map ID** ←
   שם כלשהו, סוג **JavaScript**, ‏**Vector** ← Save. מעתיקים את ה-Map ID (הוא לא סוד).
7. **תקציב ועצירה מוחלטת:** ‏**Billing ← Budgets & alerts ← Create budget** עם סכום קטן (למשל 5$) והתראות.
   תקציב לבדו רק שולח מייל ולא עוצר שימוש. כדי שחריגה תעצור את הכול, מחברים לתקציב התראת Pub/Sub עם פונקציה
   שמנתקת את החיוב מהפרויקט (בתיעוד של Google Cloud: "Disable billing with budget notifications").
   מומלץ להגדיר את זה בכל מקרה (ראו ההערה על ComputeRouteMatrix בסעיף 5). בשימוש רגיל באתר, המכסות היומיות
   שבסעיף 5 עוצרות את השימוש בזמן והאתר עובר ל-OpenStreetMap, כך שהעצירה המוחלטת אמורה לפעול רק אם מישהו מנצל את המפתח.

### 3. לחבר את המפתח לאתר

ב-GitHub: ‏Settings ← Secrets and variables ← Actions:
- בלשונית **Secrets** ← New repository secret ← שם: `GOOGLE_MAPS_API_KEY`, ערך: המפתח.
- בלשונית **Variables** ← New repository variable ← שם: `GOOGLE_MAP_ID`, ערך: ה-Map ID.

אחרי זה מריצים את הפריסה מחדש (Actions ← Test and deploy ← Run workflow), או פשוט עושים push.

**בדיקה:** פותחים את האתר ומחפשים. בתחתית העמוד כתוב "Google Maps". אם כתוב OpenStreetMap,
אפשר לפתוח את הקונסול בדפדפן (F12) ולחפש שגיאות כמו `RefererNotAllowedMapError` או `ApiNotActivatedMapError`.

## פיתוח מקומי

אין שלב build. כל האתר נמצא בתיקייה `site/`.

```bash
npm test            # בדיקות יחידה (Node 22)
npm run serve       # שרת מקומי בכתובת http://localhost:8080
npm run test:e2e    # בדיקות בדפדפן אמיתי, עם כל השירותים החיצוניים מדומים
```

בדיקות הדפדפן צריכות Playwright: `npm i -D playwright && npx playwright install chromium`.
הן מכסות את מצב OpenStreetMap, את מצב Google (מול SDK מדומה שנמצא ב-`tests/e2e/fake-google-maps.js`),
ואת המעבר האוטומטי כשהמכסה נגמרת או כשהמפתח לא תקין.

כדי לבדוק מקומית עם Google, אפשר לשים מפתח בקובץ `site/config.js` (ולא לעשות לזה commit),
ולהוסיף את `http://localhost:8080/*` להגבלות המפתח.
כדי לבדוק את מצב OpenStreetMap גם כשיש מפתח, מוסיפים לכתובת `?p=osm`.

## מבנה הקוד

```
site/
  index.html, styles.css      ממשק המשתמש (עברית, מימין לשמאל, מותאם לטלפון)
  config.js                   הגדרות (נכתב מחדש בזמן הפריסה)
  js/main.js                  חיבור הטופס, החיפוש, המפה והמעבר בין ספקים
  js/core/                    לוגיקה שלא תלויה בספק: חישוב האמצע, דירוג, פורמט, קישור לשיתוף
  js/providers/google.js      Google Maps Platform
  js/providers/osm.js         OpenStreetMap ושירותים פתוחים
  js/ui/                      השלמה אוטומטית, מפות, כרטיסי תוצאות
  data/green-line.json        יהודה ושומרון ועזה, לסינון הקו הירוק (נבנה ב-tools/build-green-line.mjs)
tests/unit/                   בדיקות יחידה (node --test)
.github/workflows/deploy.yml  בדיקות ופריסה ל-GitHub Pages
```
